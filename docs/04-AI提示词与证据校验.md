# 04｜AI 提示词、抽取策略与证据校验

> **AI负责理解，程序负责判断。** AI返回“候选事实+条件+证据”，不能直接决定最终业务事实。模型、温度、提示词都要版本化，以便固定测试复现。

## 一、不要用一个超长提示词一次完成全部事情

拆成三类模型调用：
- **调用A：系列候选与范围**。重点检索 Scope / Ratings / Annex / RFQ，输出相数、额定高低压、容量、互相组合关系、每条的页码原文。
- **调用B：参数规则**。按模板字段和原文段落寻找值、比较符、适用条件及语义类型；允许一次提取多个字段，但每条必须有独立证据。
- **调用C：争议项复核（按需）**。只针对冲突、图像表格、跨页表格或证据缺失调用高强度视觉模型/人工审核。

**调用前**：
1. 把 PDF 拆成有编号的页面/段落/表格，保留文档ID，防止不同文件混入一条上下文；
2. 优先提供含有 Scope、§5、§6、Annex A、技术数据表的片段，全文较长时使用召回+覆盖检查，确保不能漏掉附录；
3. 每个检索片段用 `[evidenceId | documentId | page | section]` 显式标记；
4. 如果检索信息不足，模型必须返回 `needsMoreEvidence`，由程序抓更多页；**不允许仅靠模型自信度决定字段已确证**。

## 二、提示词A：基础维度+适用范围识别

将下面文本作为系统指令模板，并用具体源PDF的 evidenceBlocks 填充用户输入：

```text
你是配电变压器技术文件结构化识别器，只分析本次给出的
documentId 对应的客户原文，不使用其他文档、不使用行业
默认规格猜值。

任务：识别“相数 + 额定高压 + 额定低压（线电压） + 容量”的
原文明确组合。不要先解析31项字段。

输出：
1. seriesCandidates[]：phase、ratedHvKv、ratedLvLineKv、
   lvRaw、capacitiesKva、combinationEvidenceIds、ambiguities。
2. scopeClaims[]：STANDARD_SERIES、EXPLICIT_SPEC、
   ORDER_CONFIRMED，分别给适用容量与证据。
3. unresolvedCombinations[]：仅看到电压集合与容量集合、但无法
   确认它们是否相互适用的情况；禁止无依据笛卡尔展开。
4. 注意Um不是额定高压、分接百分比不是额定电压；
   400/230V三相四线通常代表同一0.4kV线电压，
   若原文不是该结构则标记待核实。

必须引用提供的 evidenceId 和相关原文；没有证据的值填null
并加入待核实问题。严格返回符合 schema 的 JSON。
```

**建议的模型输出形状**：

```json
{
  "documentId": "doc11",
  "seriesCandidates": [
    {
      "phase": "3P",
      "ratedHvKv": "11",
      "ratedLvLineKv": "0.4",
      "lvRaw": "400/230V",
      "capacitiesKva": ["50","75","100","160","200","250","315","500","630"],
      "combinationEvidenceIds": ["ev_doc11_p12_0551"],
      "ambiguities": []
    }
  ],
  "scopeClaims": [
    {"scopeType":"STANDARD_SERIES","capacitiesKva":["50","75","100","160","200","250","315","500","630"],"evidenceIds":["ev_doc11_p12_0551"]},
    {"scopeType":"EXPLICIT_SPEC","capacitiesKva":["75"],"evidenceIds":["ev_doc11_p5_scope"]}
  ],
  "unresolvedCombinations": [],
  "needsMoreEvidence": false
}
```

这里的 JSON 是设计中的**期望输出示例，不表示实际 API 已返回它**。AI引用的 `evidenceId`必须在本地证据库中查得、且该片段确实包含相应值。

## 三、提示词B：按产品范围抽取参数规则

```text
你是电力变压器参数规则抽取器。
输入是一份客户源文档的文本证据块、字段模板、有证据的产品列表。
输出不是逐产品Excel，也不是最终确定参数。
目标是将原文转为可机读规则parameterRules[]。

每条规则必须给：
semanticName / fieldCode(如果能映射到模板)
rawValue / normalizedValue / unit / operator
semanticType(规范上下限/厂家保证/测量/测试允差/参考)
applicability(适用phase、额定高低压、容量eq/gte/lte等)
scope(专属/分档/全系列)
evidenceIds / rawExcerpt / uncertainty。

特别禁止：
- 把“空载200W”填进单位为% 的“空载上限”模板字段。
- 把测试损耗偏差+10%当成空载损耗W。
- 把针对75kVA的200W/910W继承给所有容量。
- 把Um12kV当作11kV产品的新额定高压。
- 把“Vendor to state”编成具体值。
- 把其他PDF的参数当作本PDF来源。
- 把“≤4%”转成不带比较符的实测4%。

遇到中文批注/澄清与正文冲突，分别返回候选和原文证据，
并标记needsHumanReview=true，不自行裁定。
```

**阻抗三档期望规则**：

```json
[
  {
    "semanticName": "impedance",
    "operator": "<=",
    "normalizedValue": "4",
    "unit": "%",
    "semanticType": "REQUIREMENT_LIMIT",
    "applicability": {"capacityKva": {"lte":"315"}},
    "evidenceIds": ["ev_doc11_p12_0581"]
  },
  {
    "semanticName": "impedance",
    "operator": "<=",
    "normalizedValue": "5.5",
    "unit": "%",
    "semanticType": "REQUIREMENT_LIMIT",
    "applicability": {"capacityKva": {"eq":"500"}},
    "evidenceIds": ["ev_doc11_p12_0581"]
  },
  {
    "semanticName": "impedance",
    "operator": "<=",
    "normalizedValue": "6",
    "unit": "%",
    "semanticType": "REQUIREMENT_LIMIT",
    "applicability": {"capacityKva": {"eq":"630"}},
    "evidenceIds": ["ev_doc11_p12_0581"]

```

此处省略文档ID等公共字段，真正落库时它们必填。**模型识别出三条规则，不需要分别提问9次阻抗**；交给程序批量匹配，提高可靠性与成本可控性。

## 四、原文抽取与适用判断——如何用代码实现

建议分两个层次：

**第一层：确定性线索搜索**
- 标题/语句匹配 `Rated kVA`、`Transformer ratings shall`、`No load loss`、`load loss`、`Impedance`、`Primary voltage`、`No. of phases`；
- 数值+单位扫描：`\d+(?:\.\d+)?\s*(?:kVA|kV|V|Hz|W|%)`；
- 关键词对应语义如 `up to`/`not exceed`/`for 75kVA`/`for each rating`/`Vendor to state`。
- 这些仅用于**候选召回和人工定位**，不能单靠正则生成最终产品清单。

**第二层：模型语义判断**
- “up to 315kVA”转 `capacity <=315`；
- “75 kVA”转 `capacity ==75`；
- “Copper wire or strip for all ratings”转 `scope DOCUMENT_WIDE`；
- “table gives value only for 75”不等于“所有容量都适用75的值”。

## 五、证据验证器必须自己做，不依赖模型自称准确

伪代码：

```python
def verify_candidate(candidate, evidence_store):
    errors = []
    for eid in candidate["evidenceIds"]:
        item = evidence_store.get(eid)
        if not item:
            errors.append("EVIDENCE_NOT_FOUND")
            continue
        if item["documentId"] != candidate["documentId"]:
            if not is_explicitly_related(item["documentId"], candidate["documentId"]):
                errors.append("CROSS_DOCUMENT_SOURCE")
    if not candidate_has_valid_unit(candidate):
        errors.append("UNIT_MISMATCH")
    if not candidate_condition_is_parseable(candidate):
        errors.append("INVALID_APPLICABILITY")
    # 数值不一定原样出现（比如0.4kV由400V转换），
    # 所以还要验证单位换算/推导说明；不是简单substring就通过。
    return errors
```

核验层建议另外保存`validationDetails`：
- 直接摘录：原文完全匹配；
- 单位标准化：例如400V→0.4kV，记录换算公式；
- 语义归纳：例如 Scope“75KVA”推断明确规格标签，标注来源性质；
- 人工确认：操作者选择后的解释；
- 不可验证：发出阻断或待审核。

## 六、冲突案例（必须展示给操作员）

举例：正文写“避雷器需要”，中文批注写“澄清不需要避雷器”。
- 保存 `candidateA=(required, BODY)` 与 `candidateB=(not required, ANNOTATION)`；
- 不自动认定批注已通过正式批准；根据正式澄清文件和订单核实；
- 若明确获得正式澄清批准，再生成`acceptedDecision`并关联两处依据。

同样，附录的某表写了“75kVA”而另一处“Vendor to specify”时，要标注这属于“该附录字段待厂家提供”，不能把“Vendor to specify”当作新容量型号。

## 七、成本/性能策略

- 先用本地文字、表格、关键词索引确定候选页，再让AI读原文；减少重复传31页PDF给模型；
- 第一次产品识别整体对关键章节调用一次，第二次参数规则可按主题分批（电气、损耗、绝缘、结构、环境），第三次只对争议项局部复核；
- 固定 promptVersion / modelId / 输入片段ID，模型输出写原始JSON，便于缓存、复现；
- 失败重试仅解决网络/结构错误，**不应通过无限次重试“投票”解决业务冲突**；
- 对图像PDF设置扫描/OCR备选路径，但图像噪声或无法识别时标记待人工检查。

## 八、最危险的六种“看起来正确但业务错误”

| AI可能返回 | 问题 | 必须如何拦截 |
|---|---|---|
| 9个标准容量 = 采购9型号 | Scope/订单范围混淆 | ScopeClaim分开统计 |
| 11kV和12kV产品各9个 | Um误当额定高压 | 角色归一化、字段校验 |
| 400/230V拆成0.4/0.23两个产品 | 线/相电压混淆 | LV配置规则 |
| 50/100/160kVA均为200W/910W | 75kVA专属损耗被继承 | condition.matches约束 |
| 空载上限10W | +10%允差当绝对损耗 | 单位+semanticType联检 |
| 22kV产品引用11kV PDF | 跨文件“借值” | documentId证据隔离 |

## 九、结构化输出建议

通过模型 API 的 JSON Schema / Pydantic 校验结果形状，解析失败不得进入后续阶段。结构正确之后仍需做**证据和规则校验**。提示词中不要暴露数据库权限、内部 API Key 等信息；源 PDF 文本按不可信输入处理。
