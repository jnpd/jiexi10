# 06｜开发任务、里程碑与验收（可以直接拆成 GitHub Issues）

> 优先做可靠的后端闭环，不建议第一阶段就开发复杂页面/智能Agent。以下为**实施计划**，未勾选项均未开发。实际工期因开发人员、文件复杂程度和API权限而变化，不作为交付承诺。

## 1. MVP 定义

**MVP 输入**：模板xlsx + 11kV和22kV源PDF（或更多同结构PDF）。

**MVP 输出**：
- 原文证据索引（可看文档和页码）；
- 机器可读产品系列/产品行/范围声明/字段决议JSON；
- 标准全系列模式下，11kV与22kV分别9个ProductItem，按文件输出两份xlsx，每份9个Sheet，每个Sheet字段数等于模板字段数；
- 空载/负载W仅在原文给出容量的对应产品行赋值；阻抗上限按容量匹配；
- 报告冲突/未提供/待供应商，不编造值；
- 跨文档汇总明确显示范围口径。

用户能在命令行跑通，即是后续接API和UI的基础。

## 2. 分阶段研发拆解

### P0：建立可重复测试的基线（必须先做）

| 编号 | 任务 | 开发动作 | 文件/产物 | 验收 |
|---|---|---|---|---|
| P0-01 | 初始化工程 | 创建FastAPI项目、配置、依赖锁、单元测试、静态检查、环境变量例子 | `service/` `pyproject.toml` `pytest.ini` | 本地可启动、`pytest`可运行 |
| P0-02 | 导入基线资料 | 保存两份EDM PDF和31字段模板的**合法测试副本**或安全的私有 fixture 引用 | `tests/fixtures/manifest.json` | 文件hash、基线数据可重放；客户涉密文件不推公共Git |
| P0-03 | 人工金标准 | 对11/22kV分别标注系列、Scope、75kVA损耗及3档阻抗来源页 | `tests/expected/*.json` | 至少有可逐字段比对的“标准答案” |
| P0-04 | 代码契约 | Pydantic定义 FieldDefinition、EvidenceBlock、SeriesCandidate、ScopeClaim、ProductItem、ParameterRule、FieldDecision | `app/models/*.py` | Schema单测通过 |
| P0-05 | CI检查 | 格式/单测/安全静态检查；不放API key和客户原件 | `.github/workflows/test.yml` | 每次PR自动运行核心测试 |

**P0出场条件**：没有基线数据和契约不得先写通用Agent；否则输出错了难以定位是“模型读错”还是“规则写错”。

### P1：解析链路（先不用UI）

| 编号 | 任务 | 具体函数/模块 | 输入/输出 | 验收 |
|---|---|---|---|---|
| P1-01 | 模板读取 | `template_reader.read_template()` | xlsx → FieldDefinition[] | 31字段、顺序、单位正确；32字段无需改代码 |
| P1-02 | PDF页面索引 | `document_reader.index_pdf()` | PDF → EvidenceBlock[] | 第12页5.5.1可定位；表格结构不乱 |
| P1-03 | XLSX文件适配器 | `document_reader.index_xlsx()` | xlsx → 单元格证据 | 明确sheet/cell位置 |
| P1-04 | 系列AI抽取 | `ai_extractor.extract_series()` | 证据 → SeriesCandidate[] + ScopeClaim[] | 返回四维维度及证据 |
| P1-05 | 范围审查 | `scope_resolver.resolve()` | Scope/Annex/RFQ候选 → 范围声明 | 标准9规格和明确75分开 |
| P1-06 | 展开去重 | `product_expander.expand()` | 有证据组合 → ProductItem[] | 不跨组合笛卡尔积、不重复0.23kV |
| P1-07 | 参数规则AI抽取 | `ai_extractor.extract_parameter_rules()` | 证据+字段 → ParameterRule[] | 3档阻抗、75专属损耗有condition |
| P1-08 | 参数适用引擎 | `parameter_resolver.resolve()` | Product+规则+字段定义 → FieldDecision[] | 9×31、75专属W不串值 |
| P1-09 | 来源/单位校验 | `validator.validate()` | 决议+证据 → ValidationIssue[] | W/%混写、跨文档、无页码失败 |
| P1-10 | Excel渲染 | `excel_writer.export_document()` | 单文档Product+确认数据 → .xlsx | 每产品Sheet+模板全部字段 |
| P1-11 | CLI调度 | `python -m app.cli parse ...` | 模板+PDF目录 → JSON/Excel/报告 | 一条命令运行全部流程 |

**P1出场条件**：输入2份EDM，技术系列模式生成两份xlsx且每份9Sheet；对标准金答案逐项比对，不能只看Sheet数量。

### P2：服务化+人工审核

| 编号 | 任务 | 具体动作 | 验收 |
|---|---|---|---|
| P2-01 | 建库和迁移 | 建任务/模板/文件/证据/系列/规则/决议/审计表 | 迁移可升级回滚 |

| P2-04 | 产品列表API | 按源文件查看大类、产品行与范围标签 | 可筛选标准/明确/订单 |

**P2出场条件**：业务人员无需命令行，能够自己上传、检查差异、确认并下载正确 Excel。

## 3. 技术依赖与开发前准备

### 服务端

Python 3.11+、FastAPI、Pydantic、PDF解析工具（PyMuPDF/pdfplumber）、XLSX工具、关系数据库、可访问的模型服务与 API Key、合规的文件存储。

初始命令（**拟建工程后**适用，不代表当前仓库存在）：

```bash
git clone https://github.com/jnpd/jiexi10.git
cd jiexi10
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
# 等P0-01添加pyproject.toml后:
pip install -e ".[dev]"
pytest -q
```

### 最小CLI契约（等P1-11实现）

```bash
python -m app.cli parse \
  --template "./data/参数确认表.xlsx" \
  --input-dir "./data/specs" \
  --export-mode STANDARD_SERIES \
  --out "./output"
```

预期：
```text
output/
  manifest.json
  source-11kv/products.json
  source-11kv/evidence.json
  source-11kv/decisions.json
  source-11kv/逐产品参数.xlsx

## 5. 质量指标（建议作为验收阈值，非现有实测）

- 产品四维识别：本次基准样本100%符合金标准；新增客户复杂样本应按相数/电压/容量分别统计准确率及召回率，而不仅算总数。
- 证据可核验率：输出为`FOUND*`的字段须100%有合法源引用；原文不支持的候选不得标`FOUND`。
- 参数字段完整率：100% = 每Sheet模板行数等于模板字段总数。
- 跨文件串值：0；无依据套用75kVA损耗到其它容量：0；误把技术规格当订单确认：0。
- 确认前阻断问题应为0；非阻断的“未提供/供应商待填”允许保留，但必须清晰展示。
- 输出准确：每源文档Excel数=1；Sheet数=选择导出范围内独立产品行数；至少人工抽查产品名称、阻抗、损耗、证据。

```

## 7. 在何处停下要求人工决策

- 源文件无法区分额定高压与Um、或低压多个输出关系不清楚；
- 标准列容量系列但 Scope/订单有范围冲突；
- 客户批注与正文冲突且没有正式澄清；
- 产品需要的关键四维之一缺失，或存在多种不确定组合；
- 参数引用证据不存在、无法定位或来源跨文档；
- 与模板标准值不同（如160kVA）**只提示差异而非拦截**，除非用户配置了严格白名单政策。

**完成后可以开始 P0**：代码仓库、测试金标准、模型结构化输出、产品键与规则引擎。有了这四块，“客户再上传十份规格书”才有可复用的工程基础。
