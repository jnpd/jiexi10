# 02｜核心数据契约与产品识别规则

> **最关键的设计**：AI 的原始候选结果、程序生成的产品行、经过规则引擎的字段决议，是三份不同的数据，不能让一个模型输出直接变成最终 Excel。

## 1. 对象关系

```text
ParseTask (任务)
 ├─ ParameterTemplateVersion → FieldDefinition[] (有序字段)
 ├─ SourceDocument[] (一个客户文件一个documentId)
 │   ├─ EvidenceBlock[] (页/章节/表格/批注)
 │   ├─ SeriesCandidate[] (AI从这份文档读到的候选系列)
 │   ├─ ScopeClaim[] (规格范围身份，支持多个并存)
 │   ├─ ProductItem[] (经程序展开且本文件内去重)
 │   │   ├─ FieldDecision[] (字段数=当前模板字段数)
 │   │   └─ ReviewAction[]
 │   └─ ParameterRuleCandidate[] (条件规则及证据)
 └─ ExportArtifact[] (每源文件一个Excel + 全任务汇总)
```

## 2. 最小字段定义：模板是“字段集”，不是“客户事实”

```json
{
  "templateVersionId": "tmpl_20260929_v1",
  "templateHash": "sha256-of-xlsx",
  "fields": [
    {
      "index": 1,
      "code": "F001",
      "name": "标准",
      "category": "产品参数",
      "unit": "—",
      "required": true,
      "referenceValues": ["IEC", "GB", "IEEE"]
    },
    {
      "index": 20,
      "code": "F020",
      "name": "空载上限",
      "unit": "%",
      "required": false
    }
  ]
}
```

上方只是2项结构示例。程序在运行时从用户上传的模板**完整抽出所有字段**，本次有31个，不得用示例覆盖全部字段。字段 code 是应用内部键，name/unit 必须原样保留模板。

## 3. 证据块结构：先能定位，后谈AI准确率

```json
{
  "evidenceId": "ev_doc11_p12_0551",
  "documentId": "doc11",
  "sourceType": "PDF_TEXT",
  "page": 12,
  "section": "5.5.1",
  "bbox": [51.2, 398.1, 530.0, 449.0],
  "rawText": "Transformers ratings shall be three-phase: 50, 75, 100, 160, 200, 250, 315, 500, 630 kVA...",
  "table": null,
  "annotationId": null
}
```

支持的 `sourceType`：`PDF_TEXT`、`PDF_TABLE`、`PDF_IMAGE`、`PDF_ANNOTATION`、`XLSX_CELL`、`RFQ_DOCUMENT`、`PO_DOCUMENT`、`HUMAN_EDIT`。页面/表格定位失败时，不要填写假坐标，使用 `null`并标注证据未核实。

## 4. 系列候选和适用范围声明

```json
{
  "seriesCandidateId": "sc_doc11_a",
  "documentId": "doc11",
  "phase": "3P",
  "ratedHvKv": "11",
  "ratedLvLineKv": "0.4",
  "lvRaw": "400/230V (Y)",
  "capacitiesKva": ["50","75","100","160","200","250","315","500","630"],
  "evidenceIds": ["ev_doc11_p12_0551"],
  "scopeClaims": [
    {
      "scopeType": "STANDARD_SERIES",
      "capacitiesKva": ["50","75","100","160","200","250","315","500","630"],
      "evidenceIds": ["ev_doc11_p12_0551"],
      "status": "SUPPORTED"
    },
    {
      "scopeType": "EXPLICIT_SPEC",
      "capacitiesKva": ["75"],
      "evidenceIds": ["ev_doc11_p5_scope"],
      "status": "SUPPORTED"
    }
  ]
}
```

**范围身份不能只保存一个 `scopeType` 枚举**：75kVA既可以属于标准系列，也可能由Scope明确点名；没有订单时，不得附加 `ORDER_CONFIRMED`。

## 5. 产品唯一键和展开算法

归一化后：
- `classKey = phase|ratedHvKv|ratedLvLineKv`
- `productKey = phase|ratedHvKv|ratedLvLineKv|capacityKva`
- `documentProductKey = documentId|productKey`
- `productId`作为数据库主键另行生成，不要因改显示名称造成主键变化。

```python
from decimal import Decimal

def normalized_decimal(value: str) -> str:
    return format(Decimal(str(value)).normalize(), "f")

def make_key(item):
    assert item["phase"] in ("1P", "3P")
    return "|".join([
        item["phase"],
        normalized_decimal(item["ratedHvKv"]),
        normalized_decimal(item["ratedLvLineKv"]),
        normalized_decimal(item["capacityKva"])
    ])

def expand(confirmed_combinations):
    result = {}
    for item in confirmed_combinations:
        # confirmed_combinations 只能来自“有证据的容量-电压对应关系”
        key = make_key(item)
        if key not in result:
            result[key] = item
        else:
            result[key]["evidenceIds"] = sorted(set(
                result[key].get("evidenceIds", []) + item.get("evidenceIds", [])
            ))
    return list(result.values())
```

**反例**：文档上分别出现11/22kV和50/75kVA，却没有说明两种电压均适配两种容量。不能直接生成4种组合；应要求AI提供原文“组合关系”的证据。只有写明“两种电压各适用50、75kVA”才可展开4种。

三相400/230V：`ratedLvLineKv=0.4`，`lvRaw="400/230V"`，若只是相电压230V不要额外生成0.23kV。真正独立0.23kV低压规格必须另有直接证据。

## 6. 参数规则对象（最重要）

```json
{
  "ruleId": "r_doc11_impedance_4",
  "documentId": "doc11",
  "fieldCode": "F014",
  "semanticName": "impedance",
  "value": "4",
  "unit": "%",
  "operator": "<=",
  "semanticType": "REQUIREMENT_LIMIT",
  "condition": {
    "phase": "3P",
    "ratedHvKv": null,
    "ratedLvLineKv": null,
    "capacityKva": {"gte": null, "lte": "315", "eq": null}
  },
  "scope": "CONDITIONAL",
  "evidenceIds": ["ev_doc11_p12_0581"]
}
```

可取：
- `operator`：`=`、`<=`、`>=`、`<`、`>`、`RANGE`、`IN`；
- `scope`：`PRODUCT_SPECIFIC`、`CONDITIONAL`、`DOCUMENT_WIDE`；
- `semanticType`：`REQUIREMENT_LIMIT`（规范上限/下限）、`BIDDER_GUARANTEE`、`MEASURED`、`TEST_TOLERANCE`、`REFERENCE_ONLY`；
- `origin`：正文/图纸/附录/批注/澄清/订单；**origin与优先级不等同**，正式澄清与原文不一致要保留双方证据，确认后才能取舍。

```json
{
  "ruleId": "r_doc11_loss_75",
  "documentId": "doc11",
  "semanticName": "noLoadLoss",
  "value": "200",
  "unit": "W",
  "operator": "<=",
  "semanticType": "REQUIREMENT_LIMIT",
  "condition": {"capacityKva": {"eq": "75"}},
  "evidenceIds": ["ev_doc11_p12_table1", "ev_doc11_p13_table31"]
}
```

这里的 `noLoadLoss` 是用于命名的 W 数值，不直接属于参数模板中的 `空载上限(%)`。同样另有 `loadLoss = 910 W`，测试偏差 `+10%`是另一条独立规则。

## 7. 字段决议对象与缺失状态

```json
{
  "documentId": "doc11",
  "productKey": "3P|11|0.4|75",
  "fieldCode": "F014",
  "fieldName": "阻抗标准",
  "templateUnit": "",
  "valueDisplay": "≤4%",
  "valueNormalized": "4",
  "valueUnit": "%",
  "operator": "<=",
  "semanticType": "REQUIREMENT_LIMIT",
  "status": "FOUND_CONDITIONAL",
  "ruleIds": ["r_doc11_impedance_4"],
  "evidenceIds": ["ev_doc11_p12_0581"],
  "decidedBy": "RULE_ENGINE",
  "reviewStatus": "PENDING"
}
```

状态严格区分：
- `FOUND_SPECIFIC`：针对该产品明示；
- `FOUND_CONDITIONAL`：容量区间、额定电压等条件匹配；
- `FOUND_SHARED`：源文档中有明确全系列通用依据；
- `WAIT_VENDOR`：供应商待报，不是数值0；
- `NOT_FOUND`：原文未给；
- `NOT_APPLICABLE`：经条件判断确实不适用；
- `CONFLICT`：多个不能同时满足的来源要求；
- `UNVERIFIED`：模型发现候选但证据未核实。

原文中“75kVA空载≤200W”存在时，产品名称可以按客户规则写`空载200W`，但 FieldDecision 必须保留 `<=` 和 `REQUIREMENT_LIMIT`，避免当成厂家保证/实测。

## 8. 决议优先级与冲突策略

适用性**先于**优先级：不匹配容量区间的规则立即排除。匹配后按下列操作：
1. 过滤与本产品相关的 `documentId`，兼容经明确关联的RFQ/订单附件且要显示其来源。
2. 排除条件不满足的规则，并收集所有候选。
3. 明确针对本四维产品的规则覆盖概括性的通用规则，但若数值冲突仍展示冲突，不直接抹掉原候选。
4. 容量范围规则在对应范围内生效；真正全系列通用规则在无更具体限制时生效。
5. 正式澄清/订货约束与技术规范冲突，保留双值与来源，**人工确认最终业务决议后才批准正式导出**。
6. 无候选 `NOT_FOUND`，只存在“Vendor to state” `WAIT_VENDOR`。
7. `referenceValues`只作为差异检测对照，**绝不能反向填补客户参数**。

## 9. 产品命名固定为8段，数据不一定齐全

`材质-容量-高电压-低电压-空载-负载-阻抗-频率`

用一个纯函数 `formatProductName(confirmedProduct)`，不要让AI生成并直接信任名字：
- `material: Copper` → `铜`；缺失 → `材质待定`（不可按行业习惯默认为铜）。
- `capacityKva` → `75kVA`；额定高压`11kV`；三相线电压`0.4kV`。
- `noLoadLossW`缺失 → `空载待定`；明确200W → `空载200W`。
- `loadLossW`缺失 → `负载待定`。
- `impedance`为限值 `<=4%` → 按用户命名要求缩成 `4%`，但显示字段保留 `≤4%`。
- `frequencyHz`缺失 → `频率待定`。

例：`铜-75kVA-11kV-0.4kV-空载200W-负载910W-4%-50Hz`。

## 10. 校验不变量（代码必须assert/返回错误）

```text
每个DocumentProduct只能引用同一源客户文件或显式关联附件的证据
同一Document不可重复productKey
每个ProductItem的FieldDecision.code集合==模板字段code集合
任何RULE.condition与ProductItem不匹配不得被分配
所有实际值必须带数值语义（LIMIT/GUARANTEE/MEASURED/TOLERANCE）
采购已确认身份必须有订单/RFQ证据
不允许来源缺失却status=FOUND*
空载/负载W值不得写入模板%字段
同一四维产品的多个变体需单独记录variant，不悄悄增加四维产品统计
导出Sheet数==被选导出范围内的唯一documentProductKey数
```
