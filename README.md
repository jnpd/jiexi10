## 目标与不可变业务规则

- **每份客户原始文档对应一个 Excel；每个确定的具体产品对应一个 Sheet；每个 Sheet 始终包含当次《参数确认表》的全部字段**，并按模板顺序排列。
- 产品唯一业务维度：相数 + 额定高压 + 额定低压（如 400/230V 对应三相 0.4kV，不拆成两个产品）+ 额定容量。另存原始文档/证据关联；跨文件统计可去重或不去重，但必须明确统计口径。
- **系列容量 ≠ 采购范围**：技术标准提到的“可用 9 种容量”不能自动宣称“采购 9 个型号”。保留 `STANDARD_SERIES`、`EXPLICIT_SPEC`、`ORDER_CONFIRMED` 等来源身份，给用户选择导出范围。
- 缺失空载/负载损耗只能记为“空载待定/负载待定”；阻抗上限不能误写成保证实测值；测试允差不能当作损耗数值。
- 参数必须包含适用条件、单位、原文定位、原文片段、审查状态；人工修改保留修改前后记录。
- **不跨文档拼接产品、不做无依据的电压×容量笛卡尔积**；不同相数或一次电压属于不同大类。
- 不依赖固定 31 字段：模板版本决定字段集合，31 只是本次《参数确认表》的已知样本。

## 建议技术栈（待项目实际确认）

- 后端编排：Python 3.11+、FastAPI、Pydantic；PDF 页面处理用 PyMuPDF，表格处理用 pdfplumber；Excel 读写用 openpyxl。
- 智能提取：具备结构化输出/页面理解能力的模型接口，配合确定性规则和原文证据复核。
- 异步任务：初版可数据库任务队列/进程 Worker；生产建议 RabbitMQ + Worker（可与现有 Spring Boot/React 系统集成）。
- 数据与文件：MySQL + 受控对象存储/文件服务；主程序只消费“已确认的结构化成果”，不要直接依赖导出的 Excel。

## 最小闭环

```text
客户上传 PDF/Excel + 参数确认表
  → 生成可定位的页面证据
  → AI 找产品系列 / 明确适用范围
  → 后端展开并去重 ProductItem
  → AI 找带条件的参数规则
  → 规则引擎逐产品分配字段
  → 人工核对争议与缺失
  → 每个源文件生成 1 个 Excel（每产品 1 个 Sheet）
  → 可选：确认结果同步到主程序
```

## 本次回归样本（切勿误认为采购数量）

- EDM 11kV：§5.5.1 列出 50/75/100/160/200/250/315/500/630 kVA，按**全标准系列**可展开 9 个具体规格；§1 特别写 75kVA。
- EDM 22kV：同为 9 个标准系列规格；§1 同样提及 75kVA，Annex A 的容量待填写。
- 因而两份文件在 `STANDARD_SERIES` 口径下合计 18 个规格，在“实际采购”口径下**需核对 RFQ/订单，不能据此得出 18 台或 18 款采购型号**。
- 两份仅对 75kVA 给出空载 200W、负载 910W 的规范上限，其余容量损耗值待定；§5.8.1 分档规定阻抗上限 ≤4%（至315kVA）、≤5.5%（500kVA）、≤6%（630kVA）。

## 推荐开发顺序

先完成**纯后端离线 CLI**：输入两个文件和一个模板，输出产品 JSON、证据报告和逐产品 Excel，并通过回归测试。之后再开发任务 API、进度、页面核对，最后对接主程序。见 [实施手册](docs/01-逐步开发实施手册.md)。
